# Sample output

A report generated by this tool against a real multi-location provider, run through `--anonymize` so it shows the method without naming the site.

Open the `.html` file in a browser. It is self-contained: no build step, no network, no fonts to fetch.

## What to look at

**The matrix at the top.** Severity against confidence. Most audit tools report severity alone, which quietly implies every finding is equally well-evidenced. A critical finding at low confidence is a question to go answer, not an instruction to act on, and the report says which is which.

**The evidence blocks.** Each finding carries the raw strings it matched on. This is what makes the tool checkable by its own author, and it is how several false positives were caught in early versions: a count that looked plausible turned out to be matching a navigation widget, and only the evidence showed it.

**The closing section.** What the audit cannot see, listed as plainly as what it can.

## Regenerating

```bash
npm run recon -- audit -c config/my-target.local.json --anonymize "Multi-location provider"
```

Anonymisation rewrites the target's name, host, and registrable domain across findings, evidence, and URLs, including sibling hosts such as staging environments that are spelled differently from the origin.
